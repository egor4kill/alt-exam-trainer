## 🕒 Практика 2: Важность полного доменного имени (FQDN) и системного времени

### 1. Назначение и теория
Корректное время критично для протоколов безопасности: Kerberos (в домене Active Directory) отказывается работать при рассинхронизации времени более 5 минут. FQDN (Fully Qualified Domain Name) требуется для сетевой идентификации служб и почты.

### 2. Эталонные команды
* **Установка FQDN на узлах (выполнить на каждом):**
  ```bash
  # На ISP:
  hostnamectl set-hostname isp.au-team.irpo; exec bash
  # На HQ-RTR:
  hostnamectl set-hostname hq-rtr.au-team.irpo; exec bash
  # На HQ-SRV:
  hostnamectl set-hostname hq-srv.au-team.irpo; exec bash
  # На HQ-CLI:
  hostnamectl set-hostname hq-cli.au-team.irpo; exec bash
  # На BR-RTR:
  hostnamectl set-hostname br-rtr.au-team.irpo; exec bash
  # На BR-SRV:
  hostnamectl set-hostname br-srv.au-team.irpo; exec bash
  ```
* **Установка часового пояса (Asia/Yekaterinburg):**
  ```bash
  timedatectl set-timezone Asia/Yekaterinburg
  ```
* **Проверка:**
  ```bash
  hostname -f            # Выведет FQDN, напр. hq-rtr.au-team.irpo
  timedatectl status     # Time zone: Asia/Yekaterinburg (+05, +0500)
  ```

## 🌐 Практика 3: Особенности сетевого конфигурирования в ОС «Альт» (/etc/net)

### 1. Назначение и теория
В отличие от Debian/Ubuntu (`netplan`, `/etc/network/interfaces`) и RHEL (`NetworkManager`), в ОС «Альт» используется собственная подсистема **/etc/net**. Каждый сетевой интерфейс представляет собой отдельный каталог внутри `/etc/net/ifaces/<имя_интерфейса>/`, где параметры задаются отдельными файлами:
* `ipv4address` — IP-адрес с маской (напр. `172.16.1.1/24`).
* `ipv4route` — маршруты (напр. `default via 172.16.1.254`).
* `options` — тип интерфейса и параметры загрузки (`BOOTPROTO=static`, `TYPE=eth`).

### 2. Эталонные команды (на примере HQ-RTR)
* **Настройка внешнего интерфейса `enp7s1`:**
  ```bash
  echo '172.16.1.1/24' > /etc/net/ifaces/enp7s1/ipv4address
  echo 'default via 172.16.1.254' > /etc/net/ifaces/enp7s1/ipv4route
  echo -e 'BOOTPROTO=static\nTYPE=eth' > /etc/net/ifaces/enp7s1/options
  ```
* **Перезапуск сетевой службы:**
  ```bash
  systemctl restart network
  # Или перезапуск конкретного интерфейса:
  ifdown enp7s1 && ifup enp7s1
  ```
* **Проверка:**
  ```bash
  ip -br -c a        # Краткий цветной список интерфейсов и адресов
  ip r               # Таблица маршрутизации (должен быть default via 172.16.1.254)
  ping -c 2 172.16.1.254
  ```

## 🏷️ Практика 4: Что такое VLAN и зачем они нужны (IEEE 802.1Q)

### 1. Назначение и теория
VLAN (Virtual Local Area Network) логически делит один физический кабель/коммутатор на изолированные широковещательные домены. В заголовке Ethernet-кадра добавляется 4-байтный тег 802.1Q с номером VLAN ID (от 1 до 4094).
* VLAN 100: Подсеть серверов (`192.168.1.0/24`).
* VLAN 200: Подсеть клиентов (`192.168.2.0/24`).

### 2. Настройка сабинтерфейсов на роутере HQ-RTR
* **Создание каталогов сабинтерфейсов:**
  ```bash
  mkdir -p /etc/net/ifaces/enp7s2.100
  mkdir -p /etc/net/ifaces/enp7s2.200
  ```
* **Настройка VLAN 100:**
  ```bash
  echo '192.168.1.1/24' > /etc/net/ifaces/enp7s2.100/ipv4address
  echo -e 'TYPE=vlan\nHOST=enp7s2\nVID=100\nBOOTPROTO=static' > /etc/net/ifaces/enp7s2.100/options
  ```
* **Настройка VLAN 200:**
  ```bash
  echo '192.168.2.1/24' > /etc/net/ifaces/enp7s2.200/ipv4address
  echo -e 'TYPE=vlan\nHOST=enp7s2\nVID=200\nBOOTPROTO=static' > /etc/net/ifaces/enp7s2.200/options
  ```
* **Поднятие интерфейсов и проверка:**
  ```bash
  ifup enp7s2.100 && ifup enp7s2.200
  ip -br -c a | grep enp7s2
  ```

## 🔀 Практика 5: Что такое NAT и зачем он нужен (iptables & sysctl)

### 1. Назначение и теория
Локальные машины используют серые частные IP-адреса (`192.168.x.x`), которые не маршрутизируются в глобальном интернете. NAT (Network Address Translation) с действием MASQUERADE подменяет адрес источника на внешний белый IP маршрутизатора `enp7s1`.
А параметр ядра `net.ipv4.ip_forward = 1` разрешает ядру пересылать транзитные пакеты между разными интерфейсами.

### 2. Эталонные команды на HQ-RTR и BR-RTR
* **Включение форвардинга пакетов (ядро + автозагрузка):**
  ```bash
  sysctl -w net.ipv4.ip_forward=1
  echo 'net.ipv4.ip_forward = 1' >> /etc/net/sysctl.conf
  sysctl -p /etc/net/sysctl.conf
  ```
* **Добавление правила NAT MASQUERADE:**
  ```bash
  iptables -t nat -A POSTROUTING -o enp7s1 -j MASQUERADE
  ```
* **Сохранение от потери при перезагрузке (Reboot Protection):**
  ```bash
  iptables-save > /root/iptables_rules
  # Добавить в crontab -e:
  (crontab -l 2>/dev/null; echo "@reboot /sbin/iptables-restore < /root/iptables_rules") | crontab -
  ```
* **Проверка:**
  ```bash
  iptables -t nat -L POSTROUTING -v -n
  ping -c 3 ya.ru
  ```

## 🚇 Практика 6: Что такое туннелирование и OSPF (GRE & FRR)

### 1. Назначение и теория
* **GRE (Generic Routing Encapsulation):** создаёт виртуальный туннель «точка-точка» поверх публичной сети провайдера между HQ-RTR (`172.16.1.1`) и BR-RTR (`172.16.2.1`).
* **MTU 1476:** Стандартный MTU Ethernet равен 1500 байт. Заголовок GRE + внешний IP заголовок занимают 24 байта ($1500 - 24 = 1476$). Если не снизить MTU до 1476, пакеты будут фрагментироваться или дропаться!
* **OSPF (Open Shortest Path First):** динамический протокол маршрутизации. Роутеры обмениваются LSA-пакетами через туннель, используя алгоритм Дейкстры, и автоматически изучают сети друг друга.

### 2. Настройка GRE-туннеля `tun0` на HQ-RTR
```bash
mkdir -p /etc/net/ifaces/tun0
echo '10.0.0.1/30' > /etc/net/ifaces/tun0/ipv4address
echo '1476' > /etc/net/ifaces/tun0/mtu
cat << 'EOF' > /etc/net/ifaces/tun0/options
TUNLOCAL=172.16.1.1
TUNREMOTE=172.16.2.1
TUNTYPE=gre
TYPE=iptun
TUNTTL=255
BOOTPROTO=static
EOF
ifup tun0
```

### 3. Настройка OSPF через консоль `vtysh`
```bash
systemctl enable --now frr
vtysh
conf t
router ospf
 network 10.0.0.0/30 area 0
 network 192.168.1.0/24 area 0
 network 192.168.2.0/24 area 0
exit
interface tun0
 ip ospf authentication message-digest
 ip ospf message-digest-key 1 md5 123qweR%
exit
do wr mem
exit
```
* **Проверка OSPF-соседства:**
  ```bash
  vtysh -c 'show ip ospf neighbor'
  # Должен быть статус Full/Backup или Full/DROther
  ping -c 2 10.0.0.2
  ping -c 2 192.168.3.2  # Пинг сквозь туннель в сервер филиала!
  ```

## 📡 Практика 7: Что такое DHCP и зачем он нужен (dnsmasq)

### 1. Назначение и теория
DHCP (Dynamic Host Configuration Protocol) автоматически выдает клиентам IP-адрес, маску, шлюз по умолчанию (Опция 3) и адреса DNS-серверов (Опция 6) через четырёхэтапный процесс **DORA** (Discover, Offer, Request, Acknowledge).

### 2. Настройка `dnsmasq` на HQ-SRV (или HQ-RTR для клиентов)
* **В файле `/etc/dnsmasq.conf`:**
  ```ini
  interface=enp0s3.100
  dhcp-range=192.168.1.10,192.168.1.100,24h
  dhcp-option=3,192.168.1.1
  dhcp-option=6,192.168.1.2
  ```
* **Применение настроек:**
  ```bash
  systemctl restart dnsmasq
  systemctl status dnsmasq
  ```
* **Проверка на клиенте HQ-CLI:**
  ```bash
  dhclient -v enp7s1
  ip -br -c a show enp7s1
  ```

## 🔍 Практика 8: Что такое DNS и зачем он нужен, защита SSH

### 1. Назначение и теория
* **DNS (Domain Name System):** превращает понятные имена (например, `hq-srv.au-team.irpo`) в IP-адреса (прямой резолвинг) и обратно через PTR-записи (обратный резолвинг).
* **Смена порта SSH на 2026:** защищает от автоматических сканеров ботнетов, которые сканируют только дефолтный 22 порт.

### 2. Настройка DNS в `/etc/dnsmasq.conf` на HQ-SRV
```ini
interface=enp0s3.100
listen-address=192.168.1.2,127.0.0.1
domain=au-team.irpo
server=77.88.8.8
no-resolv

address=/hq-rtr.au-team.irpo/192.168.1.1
address=/hq-srv.au-team.irpo/192.168.1.2
address=/hq-cli.au-team.irpo/192.168.2.2
address=/br-rtr.au-team.irpo/192.168.3.1
address=/br-srv.au-team.irpo/192.168.3.2

ptr-record=2.1.168.192.in-addr.arpa,hq-srv.au-team.irpo
ptr-record=1.1.168.192.in-addr.arpa,hq-rtr.au-team.irpo
```
* **Направление сервера на свой локальный DNS:**
  ```bash
  # ВАЖНО: В resolv.conf строго ПРОБЕЛ, а не знак '='!
  echo 'nameserver 127.0.0.1' > /etc/net/ifaces/enp0s3.100/resolv.conf
  systemctl restart network
  systemctl restart dnsmasq
  ```

### 3. Настройка защищённого порта SSH на HQ-SRV
* В `/etc/openssh/sshd_config` раскомментировать или изменить:
  ```text
  Port 2026
  ```
* Перезапустить службу: `systemctl restart sshd`
* **Проверка с клиента HQ-CLI:**
  ```bash
  dig @192.168.1.2 hq-srv.au-team.irpo +short
  ssh -p 2026 root@192.168.1.2
  ```

## 🏛️ Практика 9: Active Directory на Samba DC (Сервер BR-SRV)

### 1. Назначение и теория
Развёртывание единого контроллера домена Windows/Linux на базе Samba AD DC с аутентификацией по билетам Kerberos.

### 2. Эталонные команды на BR-SRV
```bash
apt-get update && apt-get install task-samba-dc -y
rm -rf /etc/samba/smb.conf
samba-tool domain provision \
  --realm=AU-TEAM.IRPO \
  --domain=AU-TEAM \
  --server-role=dc \
  --dns-backend=SAMBA_INTERNAL \
  --adminpass='123qweR%'

cp /var/lib/samba/private/krb5.conf /etc/krb5.conf
systemctl enable --now samba
```
* **Интеграция DNS на HQ-SRV:**
  В `/etc/dnsmasq.conf` на HQ-SRV добавить:
  ```ini
  server=/au-team.irpo/192.168.3.2
  ```
  И выполнить: `systemctl restart dnsmasq`.
* **Проверка:**
  ```bash
  samba-tool domain info 127.0.0.1
  kinit administrator        # Пароль: 123qweR%
  klist                      # Просмотр билета TGT
  ```

## 👥 Практика 10: Локальные и доменные учётные записи

### ЧАСТЬ 1: Локальные пользователи (Практика 10.1)
* **На серверах HQ-SRV и BR-SRV:**
  ```bash
  useradd sshuser -u 2026
  echo 'sshuser:P@ssw0rd' | chpasswd
  usermod -aG wheel sshuser
  ```
* **На роутерах HQ-RTR и BR-RTR:**
  ```bash
  apt-get update && apt-get install sudo -y
  useradd net_admin
  echo 'net_admin:P@ssw0rd' | chpasswd
  usermod -aG wheel net_admin
  ```
* **Файл `/etc/sudoers`:**
  Раскомментировать строку:
  ```text
  WHEEL_USERS ALL=(ALL:ALL) NOPASSWD:ALL
  ```

### ЧАСТЬ 2: Доменные пользователи (Практика 10.2)
* **Создание пользователей на BR-SRV:**
  ```bash
  samba-tool user create hquser1 123qweR%
  samba-tool user create hquser2 123qweR%
  samba-tool user create hquser3 123qweR%
  samba-tool user create hquser4 123qweR%
  samba-tool user create hquser5 123qweR%
  
  samba-tool group add hq
  samba-tool group addmembers hq hquser1,hquser2,hquser3,hquser4,hquser5
  ```
* **Ввод клиента HQ-CLI в домен:**
  Команда `acc` под `root` ➔ Пользователи ➔ Аутентификация ➔ Домен Active Directory `au-team.irpo` ➔ пароль `123qweR%` ➔ перезагрузка `reboot`.
* **Проверка на HQ-CLI:** вход под `hquser1`, команда `id` (UID > 10000).
